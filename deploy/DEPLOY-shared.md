# Выкладка на виртуальный хостинг (Spaceweb)

Инструкция для тарифа «Старт» и подобных: виртуальный хостинг с Apache и PHP,
без root и постоянных процессов.

Сайт статический — собранные файлы плюс один PHP-файл для приёма заявок.
Ничего больше не требуется: ни Node на сервере, ни базы данных.

> **На домене уже работает старый сайт.** Тариф допускает один сайт, поэтому
> новый займёт то же место. Раздел 3 — про резервную копию, и пропускать его
> нельзя: без неё вернуть старый сайт будет неоткуда.

---

## 1. Собрать сайт

На своём компьютере, не на хостинге:

```powershell
cd C:\Users\user\QazaqTest-site
git pull
npm install
Set-Content -Path .env.production -Value 'VITE_LEAD_ENDPOINT=/api/lead.php'
npm run build
```

В `dist/` появится готовый сайт (около 6 МБ вместе с фотографиями). Там же
лежит `.htaccess` — он копируется автоматически и нужен обязательно, см. ниже.

**`VITE_LEAD_ENDPOINT` читается во время сборки.** Поменяли — пересоберите,
иначе в файлах останется прежнее значение.

---

## 2. Где что лежит

В файловом менеджере Spaceweb корень аккаунта выглядит так:

```
qazaqtest/                 ← корень аккаунта, НЕ трогать его содержимое
├── .tmb                   кэш эскизов файлового менеджера
├── .authfile              служебный файл хостинга
├── .bash_history          служебный файл хостинга
└── public_html/           ← КОРЕНЬ САЙТА, работаем только здесь
```

Всё, что относится к сайту, лежит **внутри `public_html`**. Файлы уровнем выше
принадлежат хостингу — удалять их нельзя.

Итоговая раскладка будет такой:

```
qazaqtest/
├── leads.jsonl            журнал заявок — ВЫШЕ корня сайта, недоступен снаружи
└── public_html/
    ├── index.html
    ├── .htaccess
    ├── assets/
    ├── products/
    └── api/
        ├── lead.php
        └── lead-config.php
```

Журнал намеренно лежит рядом с `public_html`, а не внутри: файл со всеми
телефонами клиентов не должен скачиваться по прямой ссылке. Путь по умолчанию
в `lead-config.php` (`__DIR__ . '/../../leads.jsonl'`) при такой раскладке ведёт
ровно сюда — менять его не нужно.

---

## 3. Резервная копия старого сайта

1. Скачайте к себе **всё** содержимое `public_html`.
2. Если у старого сайта была база — выгрузите её: *Хостинг → Базы данных →
   Экспорт*. На тарифе доступна одна база, и она, скорее всего, занята старым
   сайтом.
3. Убедитесь, что копия открывается и весит столько же, сколько на сервере.

Только после этого продолжайте. Дальше содержимое `public_html` удаляется, и
вернуть его будет неоткуда.

---

## 4. Загрузить новый сайт

1. Удалите **содержимое** `public_html` — саму папку оставьте. Копия уже есть.
2. Загрузите туда **содержимое** папки `dist/` — именно содержимое, а не саму
   папку: в `public_html` должны оказаться `index.html`, `assets/`, `products/`,
   `.htaccess`.

`.htaccess` — скрытый файл. В файловом менеджере включите показ скрытых файлов,
в FTP-клиенте — соответствующую настройку, иначе он не загрузится и **все
внутренние ссылки начнут отдавать 404**: адреса вида
`/catalog/asphalt/press-lwd-5b` существуют только внутри приложения, на диске
таких файлов нет, и без правила переписывания сервер их не найдёт.

## 5. Куда приходят заявки

Каналов два, и они независимы. Заявка в любом случае пишется в журнал на
диск — уведомление только избавляет от необходимости туда заглядывать.

**Почта — основной канал на Spaceweb.** Письмо уходит через почтовый сервер
самого хостера: наружу ходить не требуется, SPF и репутация домена у него уже
настроены. Ничего заводить не нужно, только вписать адрес в настройки.

**Telegram — только там, где хостинг выпускает соединения наружу.** Проверено
на этом аккаунте: Spaceweb соединения к `api.telegram.org` блокирует
(`curl #28: Connection timed out`), поэтому здесь канал не работает и `tg_token`
нужно оставить пустым. Если поддержка откроет исходящие на
`api.telegram.org:443`, бот заводится так:

1. Написать [@BotFather](https://t.me/BotFather), команда `/newbot`.
2. Написать своему боту любое сообщение — без этого он не имеет права вам
   писать.
3. Открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти
   `"chat":{"id":...}`.

Заполненный `tg_token` при заблокированных исходящих — не безобидная мелочь:
сообщение всё равно не уйдёт, а каждая заявка будет держать процесс PHP до
истечения таймаута.

---

## 6. Обработчик заявок

1. Создайте внутри `public_html` папку `api/`.
2. Загрузите туда `deploy/shared-hosting/lead.php`.
3. Скопируйте `lead-config.example.php` в ту же папку под именем
   `lead-config.php` и заполните адрес для писем:

   ```php
   'mail_to'   => 'info@qazaqtest.kz',
   'mail_from' => 'noreply@qazaqtest.kz',
   ```

   `tg_token` и `tg_chat` оставьте пустыми, пока Spaceweb не откроет
   исходящие соединения (см. раздел 5).

Заявка записывается в журнал и сразу подтверждается посетителю, а уведомления
уходят следом, уже без него. Поэтому форма отвечает мгновенно, даже если
Telegram недоступен, — и посетитель не ждёт у крутящейся кнопки, пока истечёт
таймаут.

Путь к журналу в `lead-config.php` менять не нужно: при раскладке из раздела 2
он ведёт в корень аккаунта, рядом с `public_html`, — то есть вне публичной
части.

---

## 7. SSL

В панели: *SSL → выпустить бесплатный сертификат* для `qazaqtest.kz` и
`www.qazaqtest.kz`, включить перенаправление на HTTPS.

---

## 8. Проверка

По порядку, не пропуская:

1. Открыть `https://qazaqtest.kz/` — главная.
2. Открыть **прямой ссылкой** `https://qazaqtest.kz/catalog/asphalt` — должен
   открыться раздел, а не 404. Если 404 — не загрузился `.htaccess`.
3. Открыть карточку товара, проверить, что видно фотографию.
4. Отправить заявку через форму на сайте и убедиться, что письмо пришло на
   `info@qazaqtest.kz` (загляните и в «Спам»).

Четвёртый шаг обязателен целиком: проверка отдельным запросом не покажет, что
в сборку попал правильный адрес обработчика. Форма должна ответить сразу — если
она «думает» несколько секунд, значит остался заполненный `tg_token` при
заблокированных исходящих.

---

## 9. Обновление в дальнейшем

```powershell
git pull
npm run build
```

Затем загрузить содержимое `dist/` поверх. Папку `api/` при этом не трогать —
она не входит в сборку и обновления не требует.

## Если что-то пошло не так

**Внутренние ссылки дают 404, главная работает.** Не загрузился `.htaccess`
(скрытый файл) или на хостинге отключён `mod_rewrite` — второе решается
обращением в поддержку.

**Форма показывает «Заявка не ушла автоматически».** Значит запрос не дошёл или
вернул ошибку:

- откройте `https://qazaqtest.kz/api/lead.php` в браузере — должно быть
  `{"error":"Method not allowed"}`. Если 404, файл лежит не там; если пустая
  страница или ошибка PHP — смотрите журнал ошибок в панели;
- проверьте, что в `.env.production` был `/api/lead.php` **до** сборки;
- проверьте в `lead-config.php`, что `allowed_origin` — ровно
  `https://qazaqtest.kz`, без слэша в конце.

**Заявки не приходят в Telegram, хотя в журнале есть.** Заявки не потеряны:
журнал пишется первым и от Telegram не зависит — скачайте `leads.jsonl`, все
обращения там.

Причина почти всегда одна: хостинг не выпускает исходящие соединения к
`api.telegram.org`. На этом аккаунте так и есть — проверено, соединение
отваливается по таймауту. Что делать:

1. Включить почту (раздел 6) и **очистить `tg_token`**, чтобы обработчик не
   ждал впустую.
2. Если Telegram нужен — написать в поддержку Spaceweb с просьбой открыть
   исходящие соединения на `api.telegram.org:443`. Когда откроют, вернуть
   токен: каналы работают независимо, можно держать оба сразу.

Проверить состояние ещё раз можно так: загрузите
`deploy/shared-hosting/check.php` в папку `api/`, откройте
`https://qazaqtest.kz/api/check.php`, прочитайте ответ и **удалите файл**. Он
покажет, есть ли curl, доходит ли соединение до Telegram и с какой ошибкой, и
отвечает ли бот.

**Форма отвечает не сразу, а через несколько секунд.** Обработчик отвечает
посетителю до отправки уведомлений, так что ждать нечего — если ожидание всё
же есть, причин две:

- в `lead-config.php` остался `tg_token` при заблокированных исходящих:
  каждая заявка упирается в таймаут. Очистить;
- ответ сжимается по пути: `mod_deflate` держит поток открытым, и браузер
  ждёт конца скрипта. В `public/.htaccess` сжатие для `/api/` отключено —
  проверьте, что на сервер попала свежая версия файла.

**Нужно вернуть старый сайт.** Удалить загруженное, вернуть на место резервную
копию из раздела 3.
