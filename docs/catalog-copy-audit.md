# Аудит текстов карточек каталога

Дата: 16.08.2026. Источник: `src/data/catalog.generated.json`, 127 позиций.
Проверялись поля `summary`, `description`, `features`, `specs`, `title`.

## Коротко

Тексты — это выгрузка чужого каталога: машинный перевод с китайского (28 позиций),
русские описания производителя ЛинтеЛ (10 позиций) и 89 позиций смешанного
происхождения. Общая проблема одна: **на сайт попал не текст, а сырьё**. Одно и то
же содержание дублируется в трёх полях, обрывается на полуслове, единицы измерения
записаны четырьмя разными способами, а половина «описаний» — это выгруженный
маркетинговый список без единого предложения о принципе работы.

Инженер, выбирающий пресс для Маршалла, не может по такой карточке ответить на три
базовых вопроса: что прибор измеряет, по какому стандарту и в каком диапазоне.

### Имена параметров не унифицированы

Один и тот же параметр в разных карточках называется по-разному, поэтому таблицы
характеристик нельзя ни сравнить между собой, ни отфильтровать:

| Параметр | Вариант А | Вариант Б |
| --- | ---: | ---: |
| Масса | «Вес…» — 58 позиций | «Масса…» — 27 позиций |
| Габариты | «Размеры…» — 72 позиции | «Габаритные размеры…» — 23 позиции |

По ГОСТ 8.417 масса измеряется в килограммах, а «вес» — это сила в ньютонах.
В каталоге лабораторного оборудования такую подмену видно сразу.

### Стандарты

## Целевая структура карточки

Одинаковая для всех 127 позиций. Поля, которых нет в источнике, остаются пустыми
и не выводятся — но структура не меняется от карточки к карточке.

| Поле | Объём | Содержание |
| --- | --- | --- |
| `title` | до 70 знаков | Тип прибора + код модели. Без «автоматический», «высокоточный» |
| `summary` | 120–200 знаков, 1–2 предложения | Что определяет, по какому стандарту, ключевой диапазон. Пишется отдельно, не режется из описания |
| `description` | 400–900 знаков, 2–3 абзаца | Абзац 1 — назначение и метод. Абзац 2 — конструкция и привод. Абзац 3 — управление, регистрация, вывод данных |
| `features` | 3–5 пунктов, до 100 знаков каждый | Только то, чего нет в описании и характеристиках: конструктивные решения, автоматизация, интерфейсы |
| `specs` | пары «параметр — значение» | Диапазон → точность → производительность → питание → габариты → масса. Именно в этом порядке |
| `standards` | список | ГОСТ / СТ РК / ASTM / EN / JTG. Новое поле, сейчас стандарты растворены в прозе |
| `package` | список | Комплектация и опции, приобретаемые отдельно. Сейчас смешаны с характеристиками |

## Редполитика

**Язык**

- Настоящее время, действительный залог: «прибор определяет», а не «прибором
  может быть определена».
- Запрещены: «данный», «настоящий», «изделие», «машина» (кроме составных
  терминов), «хост», «пользователь» → «оператор», «тестировщик» → «оператор».
- Оценки удаляются или заменяются фактом. «Высококачественный холоднокатаный
  лист» → «холоднокатаная сталь». «Надёжный контроль температуры» → «±1 °C».
  «Широко используется в дорожных лабораториях» → удалить.
- Сравнения с безымянным конкурентом («стабильность в несколько раз выше, чем у
  гидравлического оборудования») удаляются либо превращаются в измеримое
  утверждение, если в источнике есть число.
- Никаких упоминаний производителя от первого лица («наша компания»).

**Числа и единицы**

- Градус Цельсия — только `°C` с латинской «C». Символ `℃` и кириллическая `°С`
  запрещены.
- Габариты — через `×` с пробелами: `1390 × 650 × 1200 мм`.
- Десятичный разделитель — запятая: `9,525 мм`.
- Пробел между числом и единицей, кроме градуса: `50 кН`, `±1 °C`.
- Диапазон — через тире с пробелами: `5 – 31 об/мин`, температурный — `от 5 до
  200 °C`.
- Питание — словами: `380 В, 3 фазы + N` вместо `AC380V`; `220 В, 50 Гц`.
- Проценты — `0,5 %` с неразрывным пробелом.

**Имена параметров** — единый словарь на весь каталог:

`Масса` (не «Вес»), `Габариты` (не «Размеры» и не «Габаритные размеры»),
`Питание`, `Потребляемая мощность`, `Диапазон измерения`, `Точность измерения`,
`Погрешность`, `Производительность`, `Вместимость`. Прибор — `прибор`,
`установка`, `пресс`, `аппарат` по типу; «машина» и «тестер» из названий уходят.

**Структура характеристик**

- Одна строка — один параметр. Слитые пары разбиваются:
  `Максимальное давление: 50 кН Точность: 0,5%` → две строки.
- Строки-заголовки (`Параметры питания:`) удаляются, вложенные пункты
  поднимаются на верхний уровень с полным именем параметра.
- Маркеры `•` в начале строк убираются — списком управляет вёрстка, а не текст.

### 2. Переводная «вода» + неразличимое название

**Было** — «Тестер стабильности Маршалла» (одно из девяти одинаковых названий),
1 400 знаков про «интегрированную общую конструкцию» и «запатентованный алгоритм
компании», характеристики со слитыми парами.

**Стало:**

- **Название:** Пресс для испытания по Маршаллу LWD-5B
- **Аннотация:** Определение стабильности и условной пластичности образцов
  асфальтобетона по Маршаллу. Нагружение до 50 кН со скоростью 50 ± 5 мм/мин.
- **Описание:** Пресс для испытания образцов асфальтобетона по Маршаллу.
  Нагружение выполняет шаговый двигатель с низкоскоростным редуктором в замкнутом
  контуре по скорости; рабочая частота вращения 100 об/мин снижает вибрацию и шум.

  Управление и индикация — на встроенном 10-дюймовом сенсорном экране с
  отображением кривой нагружения и хранением результатов. Алгоритм определяет
  точку разрушения по предварительному сжатию образца.

  Данные передаются на ПК по USB; программное обеспечение экспортирует кривые
  испытания и формирует протокол.
- **Особенности:** замкнутый контур по скорости нагружения · встроенный сенсорный
  экран 10″ с хранением кривых · экспорт кривых и протокол испытаний через ПО для
  ПК · подключение по USB
- **Характеристики:** Максимальная нагрузка 50 кН · Точность измерения нагрузки
  0,5 % · Скорость нагружения 50 ± 5 мм/мин · Диапазон измерения текучести 25 мм ·
  Точность измерения текучести 0,5 % · Диаметр индентора Ø 152,4 мм ·
  Потребляемая мощность не более 1 кВт · Питание 220 В, 50 Гц · Габариты
  665 × 510 × 755 мм · Масса нетто 110 кг
- **Комплектация и опции:** сетевое подключение или ПО для ПК · струйный принтер

Название с кодом модели снимает главный дефект каталога: девять позиций
превращаются в LWD-3A … LWD-5B и становятся различимы в выдаче и в поиске.

Отдельно про терминологию: в источнике параметр назван «Диапазон значений
расхода» — это машинный перевод английского *flow value*. По Маршаллу это
текучесть (условная пластичность), и лаборатория ищет карточку именно по этому
слову. Таких подменённых терминов в каталоге много; их правка — половина работы
над «инженерностью» текста.

### 3. Русский первоисточник, выгруженный списком

**Было** — описание начинается с `• программный нагрев образца…`, семь буллетов
подряд, среди них разорванный на две строки пункт «до / 300 результатов
испытаний», в конце — врезка «Описание товара» со ссылкой на МИ 2418-97.

**Стало:**

- **Название:** Аппарат для определения температуры размягчения по кольцу и шару
  (ЛинтеЛ)
- **Аннотация:** Автоматическое определение температуры размягчения нефтяных
  битумов по ГОСТ 11506-73 в диапазоне от 5 до 200 °C, два образца одновременно.
- **Описание:** Аппарат определяет температуру размягчения нефтебитумов и других
  битуминозных материалов методом кольца и шара. Нагрев жидкости в термостате
  идёт по программе со скоростью 5 ± 0,5 °C/мин.

  Аппарат автоматически фиксирует температуру размягчения двух образцов,
  останавливает испытание по его окончании и подаёт звуковой сигнал. Результаты
  выводятся на 4-строчный ЖК-дисплей, память хранит до 300 измерений с выводом
  на печать через RS-232.

  Геометрия колец, шарика и расстояние до контрольного диска соответствуют
  ГОСТ 11506-73.
- **Особенности:** одновременное испытание двух образцов · программный нагрев
  5 ± 0,5 °C/мин · память на 300 результатов · передача данных по RS-232
- **Характеристики:** Диапазон температур размягчения от 5 до 200 °C · Скорость
  нагрева 5 ± 0,5 °C/мин · Точность термостатирования ±1 °C · Дискретность
  измерения 0,1 °C · Питание 220 В (+22/−33 В), 50 ± 1 Гц · Потребляемая мощность
  не более 1200 В·А · Габариты не более 400 × 275 × 280 мм · Масса не более 15 кг ·
  Гарантийный срок 24 месяца
- **Стандарты:** ГОСТ 11506-73 · МИ 2418-97
- **Комплектация и опции:** беспроводная передача в «ЛинтеЛ-ЛИС» через «ПБИ
  ЛинтеЛ-Линк» — приобретается отдельно

Параметры колец и шарика (внутренний диаметр 15,9 ± 0,2 мм и т. д.) — это не
характеристики прибора, а требования ГОСТ к оснастке. Их место в разделе
«Комплектация», а не в таблице характеристик.

## План работ

Проходы 1 и 2 **выполнены** и живут в `src/data/normalizeCatalog.js`: правила
применяются к выгрузке один раз при загрузке модуля, там же, где строится
поисковый индекс. Проходы 3–6 — редактура, её место в слое overrides.

Порядок по убыванию отдачи:

1. **Названия — 21 позиция.** Добавить код модели к девяти прессам Маршалла и
   двенадцати сушильным шкафам. Час работы, снимает самый заметный дефект выдачи.
2. **Механическая чистка — все 127. Сделано.** Правилами: убрать врезку «Описание товара»,
   маркеры `•` из начала строк, нормализовать `℃`/`°С` → `°C`, `х` → `×`,
   `AC220V` → `220 В`, разбить слитые пары характеристик, удалить строки-заголовки,
   привести имена параметров к словарю («Вес» → «Масса», «Габаритные размеры» →
   «Габариты»). Дополнительно: аннотация собирается из целых предложений вместо
   обрезки по 240 символов, а «особенности», дублирующие описание, удаляются.
3. **Аннотации — все 127.** Сейчас ни одной написанной; 124 оборваны. Пишутся
   заново по шаблону «что определяет + стандарт + диапазон».
4. **`features` — все 127.** Проверка показала, что дублировали описание не 103
   позиции, а все: у остальных «особенности» были теми же буллетами, из которых
   собрано описание. Поле сейчас пустое во всём каталоге, блок «Ключевые
   особенности» на карточках не выводится. Его вернёт написанный текст — по
   3–5 пунктов на позицию.
5. **Описания без прозы — сделано.** После проходов 2–4 их осталось не 61, а 17:
   правила конвейера уже вытащили прозу из большинства маркированных списков.
   Оставшиеся 17 переписаны вручную по структуре выше.
6. **Стандарты — 94 позиции.** Проставить ГОСТ / СТ РК по методу испытания.
   Требует инженера: по данным источника стандарт неизвестен, а угадывать нельзя.

Пункты 1–2 автоматизируются. Пункты 3–5 — редактура, по 20–25 карточек за проход
с проверкой инженером. Пункт 6 без специалиста не делается.


## Что дала механическая чистка

Замер до и после на тех же 127 позициях:

| Дефект | Было | Стало |
| --- | ---: | ---: |
| Аннотация обрывается посреди слова | 124 | 0 |
| «Особенности» дублируют описание | 123 | 0 |
| Врезка «Описание товара» в тексте | 75 | 0 |
| Описание начинается с маркера `•` | 54 | 0 |
| Строка характеристик начинается с `•` | 67 | 0 |
| Строка-ярлык без значения | 6 | 0 |
| Слитые пары в характеристиках | 22 | 7 |
| `℃` и `°С` кириллицей | 49 | 0 |
| Габариты через кириллическую `х` | 22 | 0 |
| `AC220V` / `AC380V` | 13 | 0 |
| Габариты прибора под именем «Размеры» | 37 | 0 |
| Неразличимые названия | 21 | 0 |
| `_x000d_`, неразрывные пробелы | 48 | 0 |

Оставшиеся 7 слитых пар — сложные составные значения вида «Датчик давления:
100 кН, 5 кН можно выбрать 2 типа, разрешение: 0,01 кН»; их разбор ручной.
Аннотации длиннее 220 знаков (26 позиций) обрезаются по границе оборота, а не
посреди слова.

Две ловушки, на которые правила натыкались при разработке — они же причина, по
которой такую чистку нельзя писать «на глаз»:

- **Номера стандартов.** Правило «десятичная точка → запятая» превращало
  ГОСТ Р 58401.13-2019 в 58401,13-2019. Обозначения стандартов теперь прячутся
  за плейсхолдер на время замен.
- **Строки-ярлыки.** Удаление строк вида «Параметры питания:» заодно стирало
  «Основные параметры рабочих частей аппарата соответствуют требованиям
  ГОСТ 11506-73:» — то есть единственную ссылку на стандарт в карточке.
  Удаляются только короткие ярлыки без цифр.
- **`\b` и кириллица.** В JS `\b` считает словами только ASCII, поэтому
  `/^вес\b/` не совпадает с «Вес брутто». Границы слов заданы через lookahead.

Ещё одно ограничение правил: «Размеры» переименовываются в «Габариты» только
когда за именем сразу идёт значение. «Размеры рабочей пластинки» — это размер
образца, а не габариты установки, и остаются как есть.


## Проход 3: что удалось автоматизировать, а что нет

Аннотацию нельзя сгенерировать формулой, и это видно по данным:

- стандарт назван в тексте только у **17 позиций из 127** — подставлять в шаблон
  нечего;
- **94 названия** — это просто тип прибора без «для определения…», назначение из
  них не выводится;
- у **78 позиций** есть характеристика-кандидат в «ключевой параметр», но первая
  подходящая часто не та: «Скорость шпинделя: 1400 об/мин» в аннотацию не годится.

Формула умеет заполнить слоты, но не умеет выбрать, какой факт важен. Поэтому
автоматизировано другое — **отбор и проверка**:

```bash
npm run catalog:lint             # сводка нарушений, код возврата 1 при ошибках
npm run catalog:lint -- --verbose  # с текстом каждой аннотации
node scripts/check_summaries.mjs --facts  # фактолист для написания текста
```

`scripts/check_summaries.mjs` проверяет каждую аннотацию по редполитике: длина
100–220 знаков, нет обрыва многоточием, нет дублирования начала описания, нет
оценочной лексики и калек перевода, единицы по ГОСТ 8.417, текст не склеен из
пунктов списка. Режим `--facts` выдаёт по каждой проблемной позиции выжимку —
тип, подраздел, найденные стандарты, ранжированные ключевые параметры и первый
абзац прозы, — то есть всё, из чего пишется аннотация, без чтения карточки целиком.

Ход работы: 83 позиции с нарушениями → 55 → 23 → 0. Тексты лежат в
`catalog.overrides.json` (117 записей) и переживают пересборку витрины.

**Где шаблон всё-таки работает.** Однородные семейства — 13 сушильных шкафов
серий 101/202, 9 шкафов DION SIBLAB, 8 муфельных печей DION — описаны шаблоном
честно: различающие факты (объём камеры, её размеры, материал, предельная
температура, мощность) лежат в данных структурно. Шаблон плох там, где каждая
позиция уникальна.

**Чего линтер не ловит.** Он проверяет форму, а не правду. При написании
аннотаций для трёх весов предел взвешивания был взят из названия модели
(AJ-6200 → 6200 г, AB-1202 → 1200 г, ED-15H → 15 кг) — в исходных данных этого
параметра нет. Линтер такие аннотации пропустил: они были грамотными и нужной
длины. Ошибку видно только при сверке с источником, поэтому числа из этих трёх
аннотаций убраны. Для карточки поставщика неверный предел взвешивания хуже, чем
его отсутствие.


## Проход 4: особенности и оценочная лексика в описании

`scripts/check_copy.mjs` (бывший `check_summaries.mjs`) расширен на два поля:

- **`features`** — пункт длиннее 100 знаков, превосходная степень
  («самый», «единственный», «№ 1»), пункт, дублирующий характеристику из
  `specs` или предложение из описания, кальки перевода;
- **`paragraphs`** — превосходная степень и оценочная лексика прямо в прозе
  описания (эти поля не режутся по длине, там уместна проза, но не реклама).

Первый прогон против уже написанных особенностей — 69 позиций из 127 с
нарушениями. Половина дефектов оказалась механической и переехала в
`normalize_catalog.mjs`:

| Правило | Позиций |
| --- | ---: |
| Пункт длиннее 100 знаков → обрезка до первого предложения или удаление | 162 пункта |
| Оценочная лексика и кальки перевода в пункте — удаление | 47 |
| Пункт дублирует характеристику из `specs` | 24 |
| Пункт дублирует абзац описания | 7 |

После этого прохода прошёл повторный `npm run catalog:lint` — 1 нарушение
осталось у одной позиции («сита лабораторные»), и это была не редактура, а
баг в самих правилах.

**Найдено при этом два повторяющихся дефекта регулярных выражений,** уже
знакомых по проходу 2:

- `\b` в JS не работает перед кириллицей, поэтому фильтр превосходных степеней
  («сам…», «единственн…») просто не отфильтровывал ничего — граница слова
  переписана через lookahead;
- знак умножения искали только среди `х`/`X`/`*`, но в маркировке сит
  встречалась заглавная кириллическая `Х` («1,2Х20») — добавлена в набор
  символов, причём в **два** места: правило для характеристик
  (`prettifyDimensions`) и правило для описаний/особенностей (`normalizeUnits`)
  раньше жили раздельно, и правка одного не чинила другого.

**Оставшиеся 35 позиций** — оценочная лексика прямо в описании — переписаны
руками в `catalog.overrides.json`. 21 из них — два повторяющихся шаблона
источника: у 13 сушильных шкафов серий 101/202 абзац был дословно один и тот
же («широко используется для сушки… в области здравоохранения»), у 8 печей
DION THERMOFUSION — тоже один и тот же текст на два абзаца. Переписаны один
раз на семейство, а не 21 раз поштучно. Остальные 14 — уникальные тексты
(«передовой прибор», «самые надёжные весы в мире», «Ваш лучший выбор» и
подобное).

После переписывания трёх описаний совпадение с уже написанными аннотациями
дало новый дубль — предсказуемо: раз оба текста писались по одной и той же
фактуре в одном стиле, они сошлись почти дословно. Переформулированы.


## Проход 5: описания без прозы

К этому проходу число позиций без прозы в описании упало с 61 (замер аудита
по сырой выгрузке) до **17** — разбор описаний на прозу и список в конвейере
(проход 2) уже вытащил абзацы там, где источник это позволял. Оставались
записи, где источник был чистым перечнем без единого вводного предложения:
семь прессов серии SYD/LWD, электромагнитный плотномер, адгезионный тестер,
секундомер и другие.

Переписаны по той же структуре, что и в проходах 3–4: назначение и метод в
первом абзаце, конструкция и режимы — во втором. Источником фактов служили
маркированные пункты сырой выгрузки (`catalog.generated.json`) — то есть та
же информация, что видел покупатель, но без циферблата надежности и без
воды.

Один нюанс здесь тот же, что и в проходе 4: переписанное описание для
измерителя теоретической плотности (qzt-86) дословно совпало с уже
написанной аннотацией — обе выросли из одного факта («вибрационный метод,
частота до 3000 Гц»). Аннотация переформулирована.

После прохода `npm run catalog:lint` — 0 нарушений по всем трём проверяемым
полям на всех 127 позициях.

## Проход 6: переход на выгрузку WooCommerce

Источником каталога стал штатный экспорт магазина rutestin.com вместо старой
выгрузки из Excel. Позиций 127 → 135; ни одна прежняя не пропала, все 127
правок остались на своих карточках — они привязаны к `wpId`, а не к порядковому
номеру.

**Что выгрузка дала сверх Excel.** Excel отдавал характеристики и особенности
отдельными колонками, CSV — одним полем `Описание` с разметкой. Но разметка в
магазине единообразна: жирный подзаголовок («Характеристики товара», «Главная
особенность», «Описание товара»), под ним `<ol>/<ul>` или строки-абзацы. Разбор
этой структуры в импортёре вернул поля на место и добавил сверх прежнего:

| Поле | Excel (127) | WooCommerce (135) |
| --- | ---: | ---: |
| характеристики | 100 | 118 |
| особенности | 73 | 79 |
| код модели | 91 | 107 |
| бренд | 45 | 112 |
| цена | 54 | 64 |

Бренд вырос вчетверо потому, что в магазине под него заведена отдельная колонка,
а в Excel он угадывался по названию. Код модели — потому что магазин пишет его
в названии как «Модель: LHRS-6».

**Чего выгрузка не дала.** Разделы «Укреплённые грунты», «Минеральные порошки»,
«Битумные эмульсии» и «Неразрушающий контроль» остались пустыми: таких позиций
нет и в российском магазине. Пополнить их из этого источника нельзя.

**Ошибки, которые пришлось поймать по дороге.**

- Категории в магазине — дерево «Раздел > Подраздел», причём разделом служит
  верхний уровень. Прежний резолвер смотрел только на лист, и из 135 позиций
  разобрал 12: витрина ужалась до огрызка. Отсюда же флаг `--dry-run` — импорт
  не должен затирать файл, пока сопоставление не проверено.
- Блок характеристик в части карточек набран не списком, а строками-абзацами.
  Обработчик искал только `<li>` и молча терял весь блок — хуже, чем не разобрать:
  текст исчезал из карточки целиком. Строки разбираются, только если хотя бы
  половина из них похожа на пары «параметр — значение», иначе это проза.
- Характеристика «Модель» у весов и термометров — шапка таблицы всего модельного
  ряда: у CAS ED-15H там стоит ED-3-H. Значение принимается, только если код есть
  в названии позиции.
- Пустая цена выгружается нулём. Без проверки 71 позиция получила бы ценник
  «0 ₸» вместо «Цена по запросу».
- Название «Модель рециклера трихлорэтилена» — не модель, а машинный перевод
  «Trichloroethylene recycler model». Шаблон «Модель X» без двоеточия принимается
  только если дальше действительно код (`LM-IV`, `CF-CA`), а не текст.

**Тексты новых позиций.** Восемь карточек пришли с прозой магазина и дали восемь
нарушений редполитики: «передовой прибор», «надёжность», аннотация дословно
повторяет первый абзац, у одной — 23 знака, у другой 286. Переписаны по той же
структуре, что и остальные 127. `npm run catalog:lint` — 0 нарушений на 135
позициях.

**Осталось решить.** В магазине две установки Лос-Анджелес с одним обозначением
DM-II (`wp-497` и `wp-1053`) и разными ценой и характеристиками. Похоже на
дубль в источнике — вопрос к поставщику, а не к скрипту.

## Проход 7: фотографии и то, что они показали

134 снимка из 135 скачаны из медиатеки магазина в `public/products/`. Одна
позиция (`wp-283`, пресс Matest) отдала сетевую ошибку — повторный запуск
`npm run images:download` дотянет только её, уже скачанное пропускается.

С фотографиями карточки стали читаться целиком, и вылезло то, чего не видно в
JSON:

- **Заголовок рвался посреди слова** — «низкотемпературног/о». Лечится не
  вёрсткой: 21 название было длиннее 70 знаков, установленных целевой
  структурой, а рекорд — 109 знаков у «Универсальной машины для испытания
  асфальтобетонной смеси с микрокомпьютерным сервоприводом (дорожная версия)».
  Все 21 переписаны; заодно из них ушли «машина» и «автоматический», как и
  требует редполитика.
- **`1000 W` вместо `1000 Вт`** — нормализация единиц знала про `V` и `Hz`, но
  не про `W` и `kW`.
- **`-50 °C~30 °C`** — тильда в текстах китайского происхождения означает
  диапазон, причём встречается в трёх начертаниях: `~`, `～`, `〜`.
- **«Масса всей машины»** — уточнение про сам прибор в карточке прибора.

Ещё две ошибки нашлись при правке заголовков, обе в конвейере:

- Слаг считался до применения правок, поэтому переписанное название оставляло
  адрес от старого. Теперь слаг пересчитывается после overrides, а свой слаг в
  правке уважается.
- Разведение одинаковых названий тоже шло до правок и их не видело: две
  установки Микро-Деваль получили одинаковый заголовок и не различались.
- Слаг обрезался по 70 знакам вместе с кодом модели: `…-asfaltobetona-k`
  вместо `…-kwn-05a`. Код модели — то, по чему карточку ищут, поэтому теперь он
  при обрезке сохраняется, а название режется по границе слова. Заодно ушло
  задвоение вида `barometr-bamm-1-bamm-1`.

Отдельно — ключ, под которым загрузчик записывал пути к фото. Он писал
порядковый `qzt-N`, тогда как все остальные правки переведены на
`wp-<id записи>`. Нормализатор при наличии `wp-` ключа игнорирует порядковый,
так что 134 скачанных снимка просто не появились бы на витрине, а после
следующего импорта разъехались бы по чужим карточкам.

## Ограничения

**Данных не хватает на 20 карточках.** У «Автоматического уплотнителя Маршалла»,
«Вращательного (гираторного) уплотнителя», «Устройства Лейтнера» и ещё 17 позиций
в источнике одна-две характеристики и три строки описания. Инженерное описание из
них не собрать — нужны паспорта приборов от поставщика.

**Соответствие стандартов не выводится из текста.** Семь позиций ссылаются на
китайский JTG E20-2011. Заменять его на «аналог ГОСТ» без проверки нельзя: для
лаборатории, проходящей аккредитацию, неверная ссылка на стандарт хуже её
отсутствия. Такие места помечаются как требующие подтверждения.

**Цены не проверялись** — аудит только текстовый.

## Где хранить отредактированные тексты

`catalog.generated.json` перезаписывается генератором из Excel, поэтому править
его напрямую бессмысленно — правки исчезнут при следующей выгрузке.

В PR #4 добавлен ровно тот слой, который здесь нужен: `catalog.overrides.json` +
`npm run catalog:build`, где правка записывается по `id` позиции поверх выгрузки.
Отредактированные тексты нужно класть туда. До вливания PR #4 писать копирайт
некуда — это ещё один довод сначала свести ветки, а потом браться за тексты.
