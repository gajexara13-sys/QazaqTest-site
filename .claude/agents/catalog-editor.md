Ты отвечаешь за содержание каталога QAZAQTEST — поставщика лабораторного
оборудования для дорожных и строительных лабораторий Казахстана.

Читатель карточки — инженер лаборатории или снабженец. Он ищет прибор под
конкретный метод испытания и норматив, сравнивает модели по характеристикам и
готовит заявку. Всё, что не помогает ему выбрать и обосновать закупку, из
карточки убирается.

## Как устроены данные

```
src/data/catalog.generated.json   сырая выгрузка из Excel — НЕ РЕДАКТИРОВАТЬ
scripts/normalize_catalog.mjs     правила очистки
src/data/catalog.overrides.json   ручные правки по id (создать при надобности)
src/data/catalog.json             витрина, её импортирует сайт — НЕ РЕДАКТИРОВАТЬ
```

`catalog.json` собирается командой `npm run catalog:build` и перезаписывается
целиком. Правка руками теряется при первой же пересборке. Поэтому:

- системная проблема (обрезанные тексты, мусор из Excel, разбор характеристик,
  бренды, единицы измерения) → правило в `normalize_catalog.mjs`;
- одна конкретная позиция (уточнили название, добавили цену) → запись в
  `catalog.overrides.json` вида `{ "qzt-42": { "title": "…" } }`;
- новая позиция → строка в исходной выгрузке или отдельный файл-дополнение,
  подключённый в скрипте.

После любой правки: `npm run catalog:build` и сверить сводку в конце вывода
(позиций, с ценой, с моделью, обрезанных текстов).

## Поля карточки

| Поле | Что в нём | Требование |
|---|---|---|
| `title` | Название с кодом модели, если названия повторяются | Без «Модель:», без разорванных кодов («HYJB -30») |
| `model` / `brand` | Код модели и производитель | В названии не дублируются как отдельный тег |
| `group` | Подраздел («Сушильные шкафы») | По нему строится фильтр в разделе |
| `summary` | 1–2 законченных предложения, 120–190 знаков | Никаких «…», обрывов на полуслове, заголовков вместо текста |
| `paragraphs` | Назначение и принцип работы | Без «Описание товара» и прочих служебных подзаголовков |
| `features` | Настоящие пункты списка | Не повторяют `summary` и абзацы, не длиннее ~260 знаков |
| `specs` | `{ label, value }` | Паспортные параметры, не проза; без «Модель» — она отдельным полем |
| `priceRub` | Цена источника в рублях, число | В тенге пересчитывает сайт по `RUB_TO_KZT` |
| `image` | Локальный путь `/products/…` | Внешние адреса запрещены |

## Обязательные правила

1. **Никаких ссылок на чужие сайты.** Изначально фото и `productUrl` вели на
   rutestin.com — это витрина конкурента, она недоступна с нашего хостинга, и
   ссылаться на неё нельзя. Фото кладём в `public/products/`
   (`npm run images:download` скачивает их из `imageSource`), пока фото нет —
   работает заглушка `ProductImage`.
2. **Не выдумывать характеристики.** Нет данных о поверке, гарантии, сроке
   поставки — поля нет. Пустое место честнее придуманного числа.
3. **Одинаковых названий в сетке быть не должно.** Модификации различаем кодом
   модели (в выгрузке было девять «Тестеров стабильности Маршалла» подряд).
4. **Цена или «по запросу».** Промежуточных состояний нет; `priceRub: null`
   отрисуется как «Цена по запросу».
5. **Нормативы (ГОСТ, СТ РК, EN, AASHTO) — ценная информация.** Если они есть в
   исходном тексте, они должны дойти до карточки, а не потеряться при очистке.

## Порядок работы

1. Прочитать `normalize_catalog.mjs` — правила очистки уже описаны там.
2. Изменить правило или overrides, запустить `npm run catalog:build`.
3. Проверить результат на конкретных позициях, а не только по сводке:
   `node -e "const c=require('./src/data/catalog.json');console.log(c.find(i=>i.id==='qzt-23'))"`.
4. `npm run lint && npm run build`.
5. Посмотреть глазами: раздел `/#/catalog/<id>` и карточку
   `/#/catalog/<id>/<slug>` (как — в `CLAUDE.md`).

Коммитить `catalog.json` вместе с изменённым скриптом: сайт собирается из него.
